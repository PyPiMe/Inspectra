# Security Policy

安全策略

## Supported versions

支持版本

Only the latest released version receives security fixes.

仅最新发布版本接受安全修复。

## Reporting a vulnerability

上报漏洞

Please report suspected vulnerabilities privately to **tbocola@gmail.com**. Do not open a public issue for security problems.

请将疑似漏洞**私下**发送至 **tbocola@gmail.com**。安全类问题请勿公开提交 Issue。

Please include:

请尽量包含：

- Affected version (see Settings → About) / 受影响版本（见「设置 → 关于」）
- Steps to reproduce / 复现步骤
- Impact and, if known, a suggested fix / 影响，以及（如已知）建议修复

We aim to acknowledge reports within 7 days and to coordinate a fix and disclosure timeline with you.

我们力争在 7 天内确认收到，并与你协调修复与披露时间线。

## Scope

范围

This project is designed for intranet-first, self-hosted deployment. Access control is expected to be provided by a front firewall/allowlist; the in-app IP allowlist is a fallback. Please evaluate your own deployment hardening accordingly.

本项目面向内网优先、自托管部署。访问控制预期由前端防火墙/白名单提供，应用内 IP 白名单为兜底。请据此评估你自身部署的加固措施。

## Please do not

请勿

- Include real credentials, tokens or internal hostnames in reports.
- 在报告中包含真实凭据、token 或内网主机名。
